# ADR 0001：采用 Rust 宿主与 Wasm 插件平台

状态：已采用

## 背景

SoftPilot 的目标是成为跨平台的软件生命周期宿主：各种软件和工具以插件形式接入，用户通过统一入口发现、安装、升级、配置、启停、卸载、恢复和诊断软件。宿主无需传统安装，首次运行选择工作区，后续升级只替换当前平台的主发布物。

平台必须同时满足：

- Windows、macOS 和主流 glibc Linux 原生桌面体验。
- 主程序自包含，不依赖预装语言运行时、WebView、Qt 或 GTK。
- 软件专有逻辑可独立演进，但不能获得任意宿主权限。
- 插件失败不能破坏宿主状态，安装与配置必须可审计、可恢复。
- GUI、CLI 和插件共享同一个宿主核心。

## 决策

- 使用 Rust stable（Edition 2024）实现宿主核心、CLI、事务引擎、平台适配器和 shim。
- 使用 Slint 实现 Windows、macOS 和 Linux GUI。
- 使用 Wasmtime 承载 WebAssembly Component Model 插件。
- 使用版本化 WIT 定义插件 ABI；插件不获得通用 WASI 网络、文件系统或进程接口。
- 使用 SQLite 保存宿主状态；所有持久状态和软件负载位于用户选择的工作区。
- 插件仓库采用 TUF 风格版本与回滚保护，插件包按内容摘要寻址并验证发布者签名。
- 不引入常驻后台服务；GUI 和 CLI 调用同一宿主用例。

## 插件执行原则

插件负责描述软件、解析目录和配置、解析版本并生成结构化操作计划；宿主负责权限判断和执行。插件不得直接访问任意网络或文件、启动任意进程、修改 Shell/注册表/系统服务，或绕过 TLS、摘要、签名、健康检查与事务阶段。

宿主仅执行已授权且通过结构化验证的计划，并为安装、升级、切换、配置、卸载和恢复记录事务日志。Component 调用必须设置 imports、fuel、内存、deadline 和返回值限制。

## 插件层级

1. 声明式 recipe：无可执行代码，覆盖标准下载、验证、解包和健康检查。
2. Wasm Component：处理动态目录、复杂版本解析和配置转换。
3. 受信任原生适配器：仅用于系统安装器、服务或无法通过宿主能力表达的平台功能；必须独立进程与单独签名。

首个可用版本只开放前两级。原生适配器在威胁模型和提权协议完成前不得向第三方开放。

## 发布模型

- Windows：单文件 `SoftPilot.exe`。
- Linux：单文件 AppImage。
- macOS：签名并公证的 `SoftPilot.app` bundle。

主发布物内嵌同版本 `spt` 和 shim 负载。宿主启动时可将这些工具原子更新到工作区，因此替换主发布物不会覆盖插件、配置和已安装软件。

## 后果

正面影响：

- Rust 适合处理不可信归档、进程和跨平台文件系统操作。
- Wasm 插件不绑定宿主 CPU ABI，崩溃或 trap 不直接破坏宿主内存。
- 软件专有逻辑与事务、安全和 UI 分离，可独立升级和审计。
- 声明式 recipe 能以较低成本覆盖大量便携软件。

代价：

- 需要维护插件 SDK、WIT ABI、权限模型、仓库签名和兼容测试矩阵。
- Slint 与 Wasmtime 增大主发布物，需要固定版本进行长期兼容验证。
- 系统安装包、服务、驱动及外部软件无法获得与工作区便携软件相同的回滚保证。
- Linux 的无需安装仍以受支持的 glibc、Wayland/X11 与桌面环境为前提。

## 替代决定

本 ADR 定义仓库唯一维护架构。旧实现不再保留在工作树中，也不构成技术或行为兼容约束；需要追溯时使用 Git 历史。
